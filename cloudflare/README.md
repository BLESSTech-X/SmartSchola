# SmartSchola — Cloudflare architecture

SmartSchola's active application stack is Cloudflare:

- **Cloudflare Pages / frontend hosting:** React application in `smartschola-frontend/`
- **Cloudflare Workers:** API, authentication, role checks and application logic in `cloudflare/src/index.js`
- **Cloudflare D1:** tenant-scoped application data in `cloudflare/migrations/`
- **Worker secrets:** external provider credentials (for example Africa's Talking SMS)

Supabase is not used by the active application. The old `backend/` and `frontend/` folders are retained as historical reference only; do not deploy them or configure the app to call them.

## D1 migrations

The configured database is `smartschola-core`. Apply migrations in order from the repository root:

```bash
cd cloudflare
npx wrangler d1 migrations apply smartschola-core --local
npx wrangler d1 migrations apply smartschola-core --remote
```

Migration files:
- `0001_smartschola_core.sql` — users, schools, memberships, sessions, login throttling, password reset tokens, academic years, classes, students, class-teacher assignments, assessments, scores and parent/student links.
- `0002_tenant_integrity_guards.sql` — cross-school integrity guards.
- `0003_school_operations.sql` — terms, subjects, attendance, fees, invoices, payments, announcements, events, notifications, audit events, school settings, timetable, admissions and subscriptions.
- `0004_settings_and_messaging.sql` — SMS settings and message history.

Do not run the SQL in a Supabase console. D1 is the source of truth.

## Worker configuration

Edit `wrangler.toml`:
- Set `ALLOWED_ORIGINS` to the exact browser origins serving the frontend.
- Set `VITE_API_URL` in the frontend hosting environment to the deployed Worker URL.
- Set `APP_ORIGIN` to the full frontend base URL if password setup links need a non-root path.

SMS delivery uses Africa's Talking through the Worker. Add credentials as Worker secrets, never as frontend variables:

```bash
npx wrangler secret put AT_API_KEY
npx wrangler secret put AT_USERNAME
```

The SMS screen records messages in D1. Delivery is unavailable until these secrets and a valid sender ID are configured.

## Platform administrator bootstrap

Platform access is separate from school membership. Create the first owner only through a trusted D1 operator session:

1. Register the initial trusted account through the Cloudflare registration flow.
2. Verify the account identity and inspect its user ID in D1.
3. Grant the platform owner role:

```sql
INSERT INTO platform_admins(user_id,role,status,created_by)
VALUES('VERIFIED_USER_ID','owner','active',NULL);
```

Never expose platform-owner provisioning through a public endpoint.

## Portal account setup

School leaders can link existing active student and parent accounts to learner records. They can also generate a one-time password setup link for an existing portal account. The token is stored as a hash in D1, expires after 24 hours, and can only be used once.

## Current migration status

The frontend's active data/auth flows are being moved to Worker endpoints. File uploads and object storage are deferred. Report export currently uses the browser print dialog; a dedicated server-generated PDF endpoint remains to be ported. Password setup links are generated by the Worker, but automatic email delivery is not configured. SMS delivery requires the secrets above.

Do not deploy or merge until the Worker, migrations, frontend build, authentication, tenant isolation, and all active school workflows have been validated together.
